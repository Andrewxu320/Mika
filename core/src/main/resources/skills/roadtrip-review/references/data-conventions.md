# 数据约定

## 标识与引用

- ID 使用小写 kebab-case 格式，在不同修订版本间保持稳定，且绝不根据数组位置生成。
- 实体映射以 ID 为键；每个值都重复相同的 `id`，以便检测意外的键漂移。
- 引用使用 ID。修订版本绝不能将同一 ID 复用于不同的现实世界实体。

## 未知项与来源

- 未知标量值使用 `null`，绝不能使用 `0`、空字符串、`TBD` 或猜测值。
- 数值 `0` 仅在它是已知且有意义的测量值时保留；绝不表示“未提供”。
- 实质性未知项还应记录在 `unknowns` 中，并附带 JSON 风格的路径和原因。
- 事实应标明其来自用户、外部来源、计算还是推断。推断在确认前始终属于提议。

## 单位与时间

- 距离使用千米，时长使用分钟，海拔使用米。
- 摘要、路段和提供商路线之间的校准最多允许 `0.1 km` 的距离差和 `1 minute` 的时长差。
- 日期使用 ISO 8601 日历日期格式。时刻使用带明确偏移量或 `Z` 的 RFC 3339 格式。
- 每个行程都应声明 IANA 时区。本地计划时间必须按该时区解释。

## 坐标与路线

- 坐标格式为 `{ "lat": number, "lon": number }`，每条包含坐标的路线都应声明 `GCJ-02` 或 `WGS84`。
- 未知坐标为 `null`；`(0, 0)` 无效。绝不能暗中混用或转换坐标系。
- 路线几何记录其提供商和查询时间。缺失的路线几何不能用直线替代。

## 修订版本与产物

- 每次变更都创建一个修订版本，其中包含稳定 ID、时间戳、父版本和原因。
- 派生产物应标明当前行程修订版本、架构版本、规则版本和生成时间。
- 接受备选方案会创建修订版本；仅提出备选方案不会改变已确认路线。

## 敏感字段

- 姓名、电话号码、身份证件、预订编号、精确家庭住址、车辆号牌、凭据和访问令牌不得出现在规范文件和可共享文件中。
- 提供商临时需要的值仅限在该次操作中使用，默认不持久化。
- 即使移除了直接身份标识，路线时间和地点仍属于敏感信息；每个可共享产物包都应提醒用户。
