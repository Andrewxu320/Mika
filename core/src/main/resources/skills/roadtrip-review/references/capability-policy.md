# 能力与适配器策略

研究前检查能力，并写入带时间戳的规范化快照。语义能力包括 `search_web`、`fetch_route`、`fetch_weather`、`fetch_traffic_events`、`fetch_elevation`、`read_user_file`、`write_artifact` 和 `open_navigation`。

每条记录包含 `status`（`available`、`limited`、`unavailable` 或 `unknown`）、提供商或 `null`、`checkedAt`、限制，以及规范化的失败信息或 `null`。未经测试的能力状态为 `unknown`，绝不能假定其可用。

## 运行模式

| 模式 | 最低可用能力 | 必须披露的信息 |
| --- | --- | --- |
| 标准 | 路线、天气、搜索和文件输出 | 提供商覆盖范围、查询时间和剩余缺口 |
| 仅搜索 | 搜索和文件输出 | 路线几何、距离、时长和当前状况的完整性均未验证 |
| 离线 | 本地读写 | 未检查当前道路和天气状况；仅评估了结构与静态规划规则 |

缺少可选能力不会中止仍有价值的工作。将当前适配器调用标记为失败，记录限制，保留先前证据，并使用不超过现有证据支持强度的关卡继续处理。缺少文件输出能力属于阻断问题，因为无法交付必需产物。

## 能力失败行为

每次调用都会更新规范化记录，包括提供商元数据、`checkedAt`、限制，以及包含稳定 `code` 和 `message` 的失败信息，或 `failure: null`。

| 语义能力 | 失败或受限时的行为 |
| --- | --- |
| `search_web` | 记录未搜索的公开来源覆盖范围；只有另一个搜索适配器仍可用时，才能继续仅搜索模式的工作。 |
| `fetch_route` | 将路线几何、距离、时长和路线可执行性标记为未验证；绝不绘制直线作为替代。 |
| `fetch_weather` | 将受影响路段的预报覆盖标记为未知，并禁止天气维度无条件通过。 |
| `fetch_traffic_events` | 记录缺少当前事件覆盖，并披露尚未验证是否不存在道路封闭。 |
| `fetch_elevation` | 将海拔剖面覆盖记录为不可用；不得根据端点推断剖面。 |
| `read_user_file` | 停止摄取该文件，保留读取失败信息，并要求提供可访问的输入。 |
| `write_artifact` | 将交付视为受阻，因为无法生成必需的本地产物包。 |
| `open_navigation` | 保持路线产物可用，并披露导航交接不可用。 |

适配器必须声明输入、规范化输出、坐标语义、时效性行为、限制和错误映射。核心策略仅使用语义能力结果。
