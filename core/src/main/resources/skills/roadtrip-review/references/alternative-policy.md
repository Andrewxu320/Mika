# B 计划策略

B 计划是有条件的路线补丁，而非文字建议。它包含触发风险、被替换路段 ID、改道起点、重新汇合点或终点、替代路段、距离和时长差值、验证状态、提供商元数据以及用户接受状态。

只有 `fetch_route` 返回的真实道路几何才能标记为 `executable`。描述性的绕行方案属于 `proposed-unverified`；其时间和距离是估算值，而非已确认事实。不完整的备选方案无法通过验证。

多个备选方案相互竞争时，应比较与安全相关的证据、增加的时间和距离、置信度、覆盖、车辆约束、过夜约束和重新汇合质量。如果较短路线的通行性证据更弱，不得仅因其更快就选择它。

生成或重新评估备选方案绝不会更改规范路线。在用户明确接受前，设置 `accepted: false`。接受备选方案会创建新修订版本，只替换声明的路段，并使受影响路段及依赖路段的评估失效。

示例：

- 完整且已验证：包含封路触发条件、准确的被替换路段、改道和重新汇合停靠点、提供商路线几何、查询时间、差值，以及 `accepted: false`。
- 完整但未验证：使用相同的补丁结构，状态为 `proposed-unverified`；没有可靠估算时，差值可以为 null。
- 不完整：缺少重新汇合点或触发条件；拒绝该方案。
- 已接受：在新修订版本中记录用户批准；绝不能因用户查看了提案就推断其已接受。
